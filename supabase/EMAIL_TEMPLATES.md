# DigiCode — Supabase Auth email templates

The emails people receive when they sign in or reset a password are **not**
generated by this codebase. Supabase sends them, from templates stored in the
dashboard, which is why they kept saying "Velora Digital" long after the site
itself was rebranded.

**Where:** Supabase Dashboard → **Authentication** → **Emails** → *Templates*.

Three templates are in use here:

| Template | Sent when | Triggered by |
|---|---|---|
| **Magic Link** | someone requests a portal sign-in code | `signInWithOtp` — `js/main.js` |
| **Confirm signup** | a player registers in Flappy Dragon | `signUp` — `flappy-dragon.js` |
| **Reset password** | either site asks for a password reset | `resetPasswordForEmail` |

> **Important for the Magic Link template:** the portal asks people to *type a
> six-digit code* (`verify.html`), not to click a link. That template must
> therefore contain `{{ .Token }}`. If it only has `{{ .ConfirmationURL }}`,
> people get a link they can't use with the form in front of them.

## The sender name is a separate setting

Changing the templates fixes the *body*. If the **From** line still reads
"Velora Digital", that comes from:

**Project Settings → Authentication → SMTP Settings → Sender name**

### Worth doing properly while you're in there

Supabase's built-in email service is rate-limited to a handful of messages per
hour and is explicitly not intended for production. With real clients signing
in to the portal, that limit will be hit, and the failure looks like "the code
never arrived" — which is indistinguishable from a broken login.

Now that `developerteam@digi-code.com.au` exists on Google Workspace, point
Supabase at custom SMTP instead:

| Field | Value |
|---|---|
| Host | `smtp.gmail.com` |
| Port | `465` |
| Username | `developerteam@digi-code.com.au` |
| Password | a Google **App Password**, not the account password |
| Sender email | `developerteam@digi-code.com.au` |
| Sender name | `DigiCode` |

The App Password comes from the Google Account → Security → 2-Step
Verification → App passwords. Sign-in emails then arrive from your own domain,
which lands in the inbox far more reliably than a shared `supabase.io` sender.
